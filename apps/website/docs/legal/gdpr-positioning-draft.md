## 1. 定性結論（請法務確認）

**使用者＝唯一 controller；Keeply＝純工具（軟體供應商），既非 processor 亦非 controller。**

核心證據只有兩條，皆為出貨版可驗證事實：

1. **零收集** — Keeply（公司）不收集任何使用資料。出貨版本的遙測程式碼未注入回報端點（`KEEPLY_TELEMETRY_URL` / `TELEMETRY_RELEASE_GATE_PASSED` 均未設定），整條管線惰性、不送出任何資料；app 的錯誤處理永不記錄檔案內容或 AI 對話內容。
2. **零中繼** — AI 功能無任何 Keeply 伺服器參與。內容由使用者裝置直連使用者選擇的 AI 服務商；Keeply 從未持有、傳輸或處理該個資。

GDPR 的 controller 定義繫於「決定處理之目的與方式」（Art 4(7)）。在本架構中，**送什麼（明確附加/勾選的檔案）、送去哪（哪家服務商或本機模型）、為什麼送（使用者自己的工作目的）全部由使用者決定**；Keeply 軟體只是執行使用者指令的本地工具，與文書處理器或瀏覽器同位。

## 2. 據以成立的設計約束（產品端已實作，引為事實）

1. Keeply 無伺服器中繼——內容由使用者裝置直送其選擇的服務商，Keeply 從未處理個資。
2. 金鑰、設定、對話記錄全在使用者本機（金鑰存 OS 安全保管庫：Windows 認證管理員 / macOS Keychain）。
3. 只送使用者明確選擇的內容；無自動掃描、無背景上傳；AI 預設關閉，未填金鑰即完全不啟用。
4. 觀測管線零內容——出貨版零傳送；即使未來啟用，設計上僅技術 metadata、永不含檔案內容或對話內容。
5. AI 服務商與使用者之間的關係由服務商條款管轄——使用者直接接受其條款、直接付費；Keeply 不是合約當事人。

## 3. CJEU Fashion ID 聯合控制者風險——反面分析

Fashion ID（C-40/17）成立 joint controllership 的前提：網站經營者**自行嵌入** Facebook Like 按鈕，從而（a）共同決定了資料蒐集與傳輸之目的（自身的商業曝光利益）與方式（嵌入行為本身觸發傳輸），且（b）傳輸不經使用者個別決定即發生。

Keeply 與該案的可區分點：

| Fashion ID | Keeply AI 助理 |
|---|---|
| 經營者嵌入元件，訪客無從選擇 | 功能預設關閉，使用者須自行填金鑰並逐次選擇內容 |
| 傳輸自動發生於頁面載入 | 每次傳輸都由使用者的明確動作觸發（附加檔案/勾選範圍/送出對話） |
| 經營者從傳輸獲得商業利益（廣告最佳化） | Keeply 不從傳輸獲得任何資料或對價（不經手費用、不加價、收不到內容） |
| 經營者選定了唯一接收方（Facebook） | 接收方由使用者選定（多家服務商或本機模型；Keeply 中性列出選項） |

結論（待法務確認）：Keeply 不「決定」目的與方式，僅提供使用者自行決定的技術手段，應不構成 joint controller。較接近的類比是郵件客戶端或瀏覽器（工具論）。

## 4. 團隊版情境附註

團隊保管庫情境下，若 team admin 為組織決定成員資料之處理（例如指示成員把含個資之檔案交給特定 AI 服務商），**該組織/admin 可能自為 controller**；Keeply 的定位不變，仍是工具。如法務認有必要，可考慮在團隊版文件中提示 admin 自身的 controller 義務（見開放問題 ③）。

## 5. 留給律師的開放問題

1. **定性站得住嗎** — 「使用者＝唯一 controller；Keeply＝純工具」在 EU / UK 監管與判例（含 Fashion ID、Wirtschaftsakademie 線）下是否成立？是否需要任何防禦性文件（如內部 accountability note）？
2. **中國服務商選項** — 產品中性列出（由使用者決定）含中國背景之服務商（如 DeepSeek）。是否需 per-locale（尤其 EU locale）額外警示或揭露？目前官網文案採中性處理（不推薦、不警告）。
3. **Art 30 記錄義務** — 零收集前提下 Keeply 自身的 Art 30 義務範圍？團隊版情境是否應提供 team admin 一份 Art 30 記錄範本（作為產品附加價值/風險緩解）？
4. **特種個資（Art 9）** — 使用者可能把健康/宗教等特種個資檔案送給 AI 服務商。是否需要 app 內升級警告（例如附加檔案時的一次性提示）？此為 app 端工作，本 memo 僅提請評估。
5. **（執行面）** terms §14.5 所附之各服務商刪除請求入口 URL 請確認最新版。
